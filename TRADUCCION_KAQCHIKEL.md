Inventario generado mediante revisión de `app/src/main/res` y búsqueda de literales en los archivos Kotlin de `app/src/main/java`. Las cadenas Kotlin figuran con archivo y línea de origen; las cadenas compartidas/duplicadas se consolidan y sus ubicaciones aparecen agrupadas. Los valores de usuario (por ejemplo, nombres de categorías, movimientos y metas) no son cadenas de interfaz traducibles.

No se añade todavía un recurso kaqchikel: las traducciones deben ser revisadas por hablantes. El código BCP 47 investigado es `cak` (Kaqchikel); la carpeta Android propuesta sería `res/values-b+cak/`, con español en `values/` como respaldo. Android documenta qualifiers BCP 47 desde API 24; en versiones anteriores al mínimo del proyecto (API 21), la app conservará el español predeterminado. El registro IANA identifica `cak` como Kaqchikel. Android permite recursos BCP 47 desde API 24. Véanse [IANA Language Subtag Registry](https://www.iana.org/assignments/language-subtag-registry/language-subtag-registry) y [Android: Providing resources](https://developer.android.com/guide/topics/resources/providing-resources).

## Hallazgos de auditoría

- Hay textos incrustados directamente en Kotlin en pantallas, diálogos, ViewModels, validadores y utilidades; quedan registrados como `Texto literal incrustado` con ubicación para migración progresiva.
- Se eliminó el recurso obsoleto `calculate_balance` junto con el botón; el cálculo automático sigue vigente.
- `strings.xml` contiene algunos valores inconsistentes o incompletos (por ejemplo, `amount` está en inglés y `goal_objective`/`current_savings` tienen capitalización distinta al resto); revisar antes de traducir.
- Los textos de educación financiera incluyen frases largas con cifras y tasas; deben traducirse como unidades completas y validarse editorialmente.
- Las cadenas con `$variable`, `${...}`, importes y porcentajes deben conservar sus marcadores. La moneda debe seguir formateándose por `CurrencyFormatter`/`formatCurrency`, no concatenando separadores traducidos manualmente.
- Categorías, nombres de usuario, nombres de movimientos y títulos escritos por el usuario son datos dinámicos y no deben traducirse. Las categorías de ejemplo/opciones fijas sí requieren recursos.
- Las opciones actuales de idioma no se aplican desde `PreferencesHelper` en el flujo activo; no hay una configuración funcional de locale ni traducción real al Kaqchikel/K’iche’.
